# Database setup

A fresh environment is set up with a single command:

```bash
php artisan migrate
```

## How it works

The historical migrations (98 files) were authored out of order, and several
tables/columns were created manually on production via the MySQL UI, so they
cannot be replayed cleanly on an empty database.

To keep the setup to one command, the production schema **and** data are shipped
as a single SQL baseline:

- `database/dump/baseline.sql` — the production dump (schema + all data:
  users, masters, etc.). **Do not edit this file** — it is the source of truth.
- `database/migrations/0000_00_00_000000_import_production_baseline.php` — a
  migration that imports `baseline.sql`. Its `0000_00_00` timestamp makes it run
  first. The dump also contains the `migrations` table with its rows, so Laravel
  treats all historical migrations as already applied and does not replay them.
- The original 98 migrations are kept for reference in
  `database/migrations_archive/` (Laravel does not scan that folder).

`app/Providers/AppServiceProvider.php` calls `Sanctum::ignoreMigrations()` so
Sanctum does not try to recreate `personal_access_tokens`, which the dump already
contains.

## Steps for a new developer

1. `composer install`
2. Copy `.env` and set the `DB_*` values. Create the empty database:
   ```sql
   CREATE DATABASE bses_needvalidation
     CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
3. `php artisan migrate`

That's it — the full schema and all data are loaded.

## Updating the baseline later

When the production schema/data changes, replace `database/dump/baseline.sql`
with a fresh `mysqldump` of production. Do not hand-edit it.
